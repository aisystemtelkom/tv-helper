# tv-helper

Local Gemma 3 inference proven through an assistant-ui chat front end. The chat
UI is scaffolding; the real target is a scanned-document validator, which is why
the model is vision-capable rather than the smallest one that can chat.

## Gotchas that will cost you time

- **Never name a script `setup` in `package.json`.** `pnpm setup` is a reserved
  built-in that modifies the shell PATH; it silently shadows the package script
  and your code never runs. The model pull is `pnpm model:pull`.
- **`src/components/*` is vendored**, generated by `assistant-ui init` and
  overwritten on upgrade. Don't hand-edit it. Its lint rules are narrowed in
  `eslint.config.mjs` for exactly this reason — don't "fix" the components.
- **Port 11435, not Ollama's default 11434.** Confirmed on this machine: the
  Windows installer auto-starts a tray app serving 11434 from `~/.ollama` with
  zero models. On the default port the app would have reached a live, empty
  server and failed as if the model pull had gone wrong.
- **`pnpm ollama:serve` refuses to start if the port is taken**, by design. It
  used to print its config banner and then fail to bind, leaving you talking to
  a stale process while believing your settings were live. If you hard-kill the
  server the child `ollama.exe` is orphaned and keeps the port — the check
  catches that on the next run and prints the command to clear it.
- **`gemma3:1b` and `gemma3:270m` have no vision tower.** Downgrading the model
  to save VRAM silently breaks the capability this project exists to prove.
- **`createLocalStorageAdapter`'s history adapter lacks `withFormat`**, which
  `useChatRuntime` hard-requires and throws without. `src/lib/threads/history.ts`
  supplies one and `store.tsx` patches it in. Replacing that with the stock
  adapter compiles fine and silently stops persisting messages.
- **Never add `xlsx` (SheetJS) from npm.** It is frozen at 0.18.5 with two
  unpatched HIGH advisories; fixes ship only from the vendor's CDN. Use
  `exceljs`, which is what `src/lib/attachments/office.ts` imports.
- **pdf.js must keep its bundled worker.** `GlobalWorkerOptions.workerSrc` is
  set from the installed package on purpose; the library's default fetches from
  a CDN, which breaks offline use and violates the client's third-party
  minimization requirement.
- **The attachment `accept` list is load-bearing.** assistant-ui's composer
  filters on it before the adapter runs, so widening it re-introduces the
  original bug: files that attach fine and then fail after send with a bare
  "An error occurred."

## The client constraint driving several decisions

Third-party minimization: the data must not leave the machine. That is why the
model is local, why sessions use IndexedDB rather than any hosted store, and why
all document conversion runs in the browser. Verify with the page open --
`performance.getEntriesByType("resource")` should show zero external hosts.

## Where things live

`src/lib/model.ts` is the only file that knows how the model is reached.
Everything upstream speaks the OpenAI chat-completions wire format, so swapping
the runtime is an env var change. Keep it that way — no Ollama SDK imports in
app code.

`pnpm smoke` (`scripts/smoke.mjs`) asserts text, streaming, and vision against
the HTTP API with no UI involved. Run it before debugging the browser; it tells
you which side of the boundary is broken.
